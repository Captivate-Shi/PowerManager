## ATK V75X 原装接收器：真机验收方案

`320F:5088` + 精确产品名 `ATK V75X 2.4G Dongle` + 同一物理 USB 父设备唯一 `FF1C:0092`，只在可验证编号 `04` 的输入/输出集合上测试。不向键盘输入集合注册或读数据，不记录按键、全局输入、设备序列号、路径或 MAC。只在人工发起一个样本时，复用已知 `04 / 16-bit sequence / 1A` 电量查询，最多一次、限时、不重试、不发配置命令。序列号应在采样间变化；它只证明这是一次新事务，不能证明返回的无线数据是新的。

1. **在线基线**：断开键盘 USB 线，接收器保持插入。由测试员手动唤醒，立刻查一次。记录发包时间、无关帧/超时、是否匹配事务、电量、充电标记。用 ATK HUB 分开查询作对照，不同时运行两套读取器。至少在高、中、低三个电量区间复验，至少含一次拔插充电线后的状态切换。
2. **关机与失联**：先取得一条在线样本，再关机或切换到其他连接方式；保持接收器插入，分别在 1、10、60 秒及睡眠阈值之后各单次查询，分开试验。若任一时点带新事务的回包仍给有效旧百分比或充电标记，仅靠 `1A` 不能用于实时电量或告警，除非另有经过验证的无线在线判据。
3. **是否唤醒**：接收器一直插着，只通过外部功耗测量确定键盘已自然进入低功耗状态（不能只看灯熄灭）。对照“同样等待但不查”和“进入睡眠后查一次”两组的电流轨迹、唤醒时间与是否妨碍下次进入睡眠；每组至少三次。若查询本身唤醒键盘，保持停用，不申请系统级键盘监听规避。
4. **干扰与恢复**：再测重新接回同一 V75X 恢复有效读数；同 VID/PID 的他牌接收器、错误产品名、集合歧义及同时插入 USB 线不能触发误发或合并错误。Windows 和固件版本各自记载，只验证采样过的组合。仅保留允许的元数据和厂商电量回包字段。

[HaloBattery 的原装接收器实机报文](https://github.com/HeyOkay/HaloBattery/blob/main/docs/protocols.md#atk-v75x)已经证明在线可读，但上游依赖特定键盘的近期输入来避免空闲查询，也明确没有硬件功耗验收；[MyFinder 的休眠/离线报文证据](https://github.com/wushuai0802/myfinder-device-battery/blob/7b4131b29709f79c833d5fb39db52656265ce9d1/docs/compatibility.md)来自共用 VID/PID 的另一款 VGN 设备和不同的 `1A 06` 查询，不能外推到 ATK。既有余电诊断候选保留，不主动查询接收器。
